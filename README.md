# Изолят

> Система раннего выявления социальной изоляции школьников на основе теории графов.

Главный пользователь — **школьный психолог**. Ученики **никогда не видят
аналитику** — они только проходят анонимный опрос по коду/QR. Из их ответов
автоматически строится ориентированный социометрический граф, а NetworkX
считает все показатели.

## Как это работает

1. Школа регистрируется и получает **код приглашения**. По нему регистрируются
   психологи и завуч — без кода доступ к данным учеников получить нельзя.
2. Психолог создаёт **класс**, добавляет **учеников** и отмечает **согласия**
   родителей на обработку данных. Без согласия ученик в срезах не участвует.
3. Психолог создаёт **срез** (опрос). Тексты трёх вопросов можно адаптировать
   под возраст класса, на русском и на казахском. Система выдаёт **ссылку + QR**
   и **одноразовые коды** — свои на каждый срез.
4. Ученик открывает страницу опроса, выбирает язык, вводит свой код и отвечает
   кнопками на три вопроса. Повторно пройти опрос нельзя.
5. Психолог **закрывает срез**. В этот момент сервер фиксирует результат и сам
   создаёт **оповещения** по тем, у кого ухудшились связи, — они ждут во
   «Входящих», а не теряются на экране одного класса.
6. Граф и метрики (изоляты, взаимные выборы, входящие/исходящие связи,
   сплочённость, мосты, компоненты, degree/betweenness centrality, density,
   сообщества) рисуются через **vis-network**. **Time Slider** переключает
   срезы, по клику на узел открывается **карточка ученика**.

## Экраны

| Экран | Кто видит | Что там |
|---|---|---|
| **Классы** | психолог | все классы, отсортированные по тому, где нужно внимание |
| **Класс** | психолог | социограмма, метрики, Time Slider, список учеников |
| **Карточка ученика** | психолог | динамика, взаимные пары, заметки, встречи, вмешательства |
| **Входящие** | психолог | оповещения, созданные сервером при закрытии среза |
| **Профилактика** | психолог | план занятий, проведение, охват, оценка эффекта |
| **Школа** | завуч, администратор | сводка по классам **без персональных данных учеников** |
| **Сотрудники** | администратор | роли, доступы, сброс паролей, код приглашения школы |
| **Журнал** | администратор | кто и когда открывал персональные данные учеников |

Windows, одной командой (локальный SQLite, ничего настраивать не нужно):

```powershell

```

Вручную (любая ОС):

```bash

```

Демо создаёт школу с тремя классами в разных состояниях — так видно, как
продукт расставляет приоритеты.

1. Войдите как **`demo@izolyat.local` / `demo12345`** (психолог с правами
   администратора школы). На главной три класса:
   8«А» с двумя оповещениями идёт первым, благополучный 9«Б» — вторым, 7«В»
   без согласий и без срезов — последним с подсказкой, что делать.
2. **«Входящие»** — оповещения по Алине Смирновой созданы сервером при
   закрытии осеннего среза, а не посчитаны в браузере.
3. Откройте **8«А» → карточку Алины**: осенью изолят, к весне взаимные пары.
   Обратите внимание, что в карточке нет списка «кто тебя выбрал» и нет имён
   тех, кто отметил её одинокой, — только числа.
4. **«Ссылка и коды»** → откройте ссылку опроса во второй вкладке, переключите
   язык на **Қаз**, введите любой код из списка.
5. **«Профилактика»** — что психолог сделал по итогам среза. Откройте эффект
   мероприятия «Включение в группу»: у охваченных связи выросли, у остального
   класса нет. Рядом — честная оговорка, почему это наблюдение, а не
   доказательство.
6. Войдите как **`zavuch@izolyat.local` / `demo12345`** — сводка по школе есть,
   а карточки учеников закрыты (403). Это граница продукта, закреплённая
   тестом `tests/test_privacy.py`.
7. **«Журнал»** — все ваши переходы уже записаны.

## Роли

- **Психолог** — работает со своими классами. Чужой класс не откроет.
- **Завуч** — видит сводку по школе: где падает связность, где низкая явка,
  каким классам нужно внимание. **Не может** открыть карточку ученика или
  узнать имена. Это граница продукта, а не забытая проверка: для
  управленческого решения нужен класс, а не ребёнок.
- **Администратор** — психолог, который завёл аккаунт школы: ведёт свои классы
  и дополнительно управляет сотрудниками.

## Что психолог видит, а что — нет

Это главная граница продукта, поэтому она проговорена явно.

- **Положительные выборы (кино, проект) психолог видит направленными.** Это и
  есть социограмма — без стрелок «кто кого выбрал» метод не работает. Ученику
  на странице опроса так и написано: «психолог видит общую картину класса».
- **Кто отметил ребёнка как «часто остаётся один» — не видит никто.** Этот
  вопрос не создаёт рёбер графа и наружу уходит только числом. Больше того,
  число показывается лишь начиная с **трёх** номинаций: одна-две — это мнение
  одного-двух детей, а не сигнал класса, и вешать по ним ярлык нельзя.
- **В карточке ученика нет списка «кто тебя выбрал».** Только счётчики и
  взаимные пары: о взаимной симпатии знают оба ученика, и именно она нужна
  психологу, чтобы действовать.

Инвариант закреплён тестами — см. `tests/test_privacy.py`.

## Профилактическая работа

Граф сам по себе ничего не меняет. Профилактика — это то, что психолог делает
по его итогам, и то, за что он отчитывается перед завучем.

**Рекомендации.** По закрытому срезу система предлагает конкретные мероприятия
с готовым ходом занятия: изолятам — включение в малую группу через того, кого
они выбрали сами (одностороннюю симпатию проще превратить во взаимную, чем
строить связь с нуля); классу с низкой плотностью — тренинг на сплочение;
разобщённым компаниям — смешанные команды. На недостоверном срезе (явка < 70%)
рекомендации не строятся вовсе.

**Занятие по ярлыку «одиночки» адресуется всему классу и никогда — ребёнку.**
Указать на него пальцем значит усилить изоляцию, а не снять её, поэтому в таком
мероприятии список участников пуст by design, а в сценарии это оговорено первой
строкой.

**План и проведение.** У мероприятия есть вид, адресат, дата, цель и ход
занятия. После проведения отмечается фактический охват — для мероприятия на
весь класс состав подставляется на момент проведения, а не планирования: за две
недели класс мог измениться. Для работы с родителями охват записывается числом:
персональных данных родителей у системы нет и не должно быть.

**Оценка эффекта.** Сравнение «до/после» по охваченным ученикам — рядом
считается то же по остальному классу. Это осознанно названо наблюдением, а не
доказательством: контрольной группы нет, и если связи выросли у всех одинаково,
дело не в занятии. Нужны два закрытых среза — до и после.

Завуч видит профилактику как отчётность: сколько проведено по каждому классу и
**в каких классах есть тревожные сигналы, но профилактика не запланирована** —
это его главный вопрос к психологу. Поимённого охвата он по-прежнему не видит.

## Достоверность: поправка на явку

«Нет входящих выборов» означает изоляцию только тогда, когда достаточная часть
класса реально прошла опрос. Иначе популярный ребёнок, чьи друзья не ответили,
выглядел бы изолятом — и психолог пошёл бы работать с ребёнком, у которого нет
проблемы.

- Статус **«изолят»** ставится только если ученика не выбрал никто **и**
  ответило ≥ 70% одноклассников. Иначе статус — **«нет данных»** (серый узел).
- Срез с явкой < 70% помечается как недостоверный: над графом появляется
  баннер, **индекс класса не считается**, а оповещения и «радар изоляции»
  отключаются.
- Плотность, взаимность и сплочённость считаются по подграфу ответивших.
- **Сводный «индекс связности» подписан как экспериментальный.** Это наша
  свёртка взаимности, плотности и доли изолятов по внутренней шкале 0–100: она
  годится, чтобы сравнивать классы между собой и с самими собой во времени, но
  с внешними нормами не сверялась, и выдавать её за измеренную величину
  нечестно. Отдельные показатели (изоляты, взаимные пары, явка) от неё не
  зависят.

## Персональные данные

В базе — ФИО, дата рождения, пол несовершеннолетних и заметки психолога об их
состоянии. Поэтому:

- **Согласия.** Ученик без действующего согласия не участвует в срезе вообще:
  ему не выдаётся код и одноклассники не видят его в списке для выбора.
  Отзыв согласия исключает его из следующих срезов.
- **Срок хранения.** У каждого класса есть `retention_until` (по умолчанию год).
  По истечении срока сырые выборы и отметки о прохождении удаляются, а
  посчитанная аналитика остаётся снапшотом: графики динамики продолжают
  работать, восстановить по ним отдельные ответы нельзя.
- **Журнал доступа.** Открытие карточки ученика, просмотр аналитики, выгрузка
  и удаление пишутся в `audit_log` — можно ответить, кто и когда смотрел
  данные конкретного ребёнка.

```bash
python -m app.retention          # показать, что будет удалено
python -m app.retention --apply  # удалить
```

- **Документы.** `/privacy.html` — политика обработки данных (что собирается,
  на каком основании, кто имеет доступ, сколько хранится, права родителя),
  `/terms.html` — условия использования с разделом «чем система не является»:
  это не диагноз, не замена специалисту и не характеристика ученика. Ссылки на
  обе страницы есть в кабинете, на экране входа и на странице опроса.

## Запуск

Нужен **Python 3.10+**. База — SQLite локально, PostgreSQL (Supabase) на
проде; код один и тот же.

### Локально

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # DATABASE_URL уже sqlite:///izolyat.db
alembic upgrade head               # создать/обновить схему
python -m app.seed                 # (необязательно) демо-данные
python run.py                      # http://127.0.0.1:8000
```

`run.py` умеет: `--port 8080`, `--no-reload` (стабильнее для показа) и `--lan`
(см. ниже). На Windows то же самое делает `.\start-local.ps1` — он ставит
переменные окружения на локальный SQLite, накатывает миграции, засевает демо и
запускает сервер, **не трогая `.env`**. Ключи: `-Fresh` (пересоздать базу),
`-Lan`, `-Port 8080`.

Открой <http://127.0.0.1:8000>, зарегистрируй школу, затем аккаунт по её коду.

Демо-аккаунты (после `python -m app.seed`):

```
Психолог + администратор: demo@izolyat.local   / demo12345
Завуч:                    zavuch@izolyat.local / demo12345
Код приглашения школы:    DEMO2026
```

### На сервере (PostgreSQL / Supabase)

Supabase → **Project Settings → Database → Connection string → URI**. Если
прямое подключение `db.<ref>.supabase.co` не коннектится — возьми **Session
pooler** (порт 5432, работает по IPv4). Спецсимволы в пароле URL-кодируй:
`@`→`%40`, `#`→`%23`, `:`→`%3A`.

```ini
# .env
DATABASE_URL=postgresql+psycopg2://postgres:ПАРОЛЬ@db.xxxx.supabase.co:5432/postgres
# длинная случайная строка: python -c "import secrets;print(secrets.token_urlsafe(48))"
SECRET_KEY=...
# непустое значение закрывает регистрацию новых школ из интерфейса
REGISTRATION_INVITE_CODE=
# origin'ы фронтенда, если он на другом домене; пусто = CORS выключен
ALLOWED_ORIGINS=
```

Затем `alembic upgrade head` и `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
(готовый `render.yaml` в корне).

## Миграции

Схема управляется **только Alembic**. `create_all` существующие таблицы не
меняет — на живой базе он молча оставил бы схему устаревшей.

```bash
alembic upgrade head                       # применить
alembic revision --autogenerate -m "..."   # создать новую после правки models.py
alembic downgrade -1                       # откатить одну
```

**База, работавшая до появления миграций**, уже содержит схему ревизии `0001`.
Один раз выполни:

```bash
alembic stamp 0001
alembic upgrade head
```

### Если приложение падает с `UndefinedColumn`

Симптом: 500 на `/api/auth/login`, в логах
`column psychologists.school_id does not exist`.

Причина: база создавалась не Alembic, а `create_all` (он стоял в `app/main.py`
до появления этого раздела). Он создаёт таблицы, **не записывая версию** в
`alembic_version`, поэтому `upgrade head` затем падает на уже существующих
таблицах. И главное: в уже существующие таблицы `create_all` **не добавляет
новые колонки никогда** — новые таблицы появляются, а старые остаются в схеме
`0001`.

Диагностика (SQL Editor в Supabase):

```sql
SELECT * FROM alembic_version;              -- нет таблицы -> Alembic не отрабатывал
SELECT column_name FROM information_schema.columns
WHERE table_name = 'psychologists' ORDER BY column_name;
```

Если таблиц 17 (полный набор), а в `psychologists` всего 5 колонок, схему
нужно догнать вручную: `alembic stamp` здесь не поможет — колонок физически
нет, а `upgrade` не пройдёт, потому что таблицы уже есть.

**Сначала выгрузи данные** (Table Editor -> Export CSV: `students`, `choices`,
`surveys`, `survey_responses`). На free tier автобэкапов нет.

```sql
BEGIN;
ALTER TABLE psychologists ADD COLUMN school_id INTEGER
  REFERENCES schools(id) ON DELETE SET NULL;
ALTER TABLE psychologists ADD COLUMN role VARCHAR(20) NOT NULL DEFAULT 'psychologist';
ALTER TABLE psychologists ADD COLUMN is_active BOOLEAN NOT NULL DEFAULT true;
ALTER TABLE psychologists ADD COLUMN token_version INTEGER NOT NULL DEFAULT 1;
ALTER TABLE psychologists ADD COLUMN last_login_at TIMESTAMPTZ;
CREATE INDEX ix_psychologists_school_id ON psychologists(school_id);

ALTER TABLE classes ADD COLUMN school_id INTEGER
  REFERENCES schools(id) ON DELETE SET NULL;
ALTER TABLE classes ADD COLUMN retention_until DATE;
CREATE INDEX ix_classes_school_id ON classes(school_id);

ALTER TABLE students ADD COLUMN is_active BOOLEAN NOT NULL DEFAULT true;
ALTER TABLE surveys ADD COLUMN closed_at TIMESTAMPTZ;

CREATE TABLE alembic_version (version_num VARCHAR(32) NOT NULL,
  CONSTRAINT alembic_version_pkc PRIMARY KEY (version_num));
INSERT INTO alembic_version VALUES ('0003');
COMMIT;
```

После этого существующие аккаунты получают `role = 'psychologist'` и
`school_id = NULL` — администратора назначь вручную:

```sql
UPDATE psychologists SET role = 'admin' WHERE email = '...';
```

`alembic.ini` намеренно без кириллицы: configparser читает его в системной
кодировке, и на русской Windows не-ASCII комментарии ломают запуск.

## Как пользоваться (полный сценарий)

### Психолог
1. **«+ Класс»** — создай класс.
2. **«Ученики»** — добавь учеников (можно импортом из Excel/CSV) и отметь
   **согласия** родителей. Без согласия ученик в срез не попадёт.
3. **«+ Срез»** — создай опрос, при желании поменяй формулировки под возраст
   класса (русский и казахский).
4. **«Ссылка и коды»** — ссылка, QR и коды на этот срез. **«Печать кодов»**
   распечатает их для раздачи. Если код подсмотрели, кнопка **«Новый код»**
   рядом с учеником перевыпустит его и удалит подложные ответы.
5. Когда класс прошёл опрос — **«Закрыть опрос»**. Сервер зафиксирует результат
   и создаст оповещения во «Входящих».

### Ученик
1. Сканирует **QR** или открывает ссылку `http://.../survey.html?survey=1`.
2. Выбирает язык (**Рус / Қаз**), вводит свой код.
3. Отвечает кнопками на 3 вопроса и жмёт **«Отправить»**.

### Чтобы ученики открыли форму со своих телефонов
- **Деплой** (например, Render): публичный URL, QR открывается с любого телефона.
- **Одна Wi-Fi:** `python run.py --lan` (или `.\start-local.ps1 -Lan`). Скрипт
  сам найдёт адрес компьютера в сети и напечатает его. **Кабинет открывай по
  этому адресу** (`http://192.168.x.x:8000`), а не по `127.0.0.1`: ссылка и QR
  берутся из адресной строки, и с localhost телефон их не откроет. Если порт не
  отвечает — его закрыл брандмауэр Windows.

## Безопасность

- Ученики не являются пользователями — они физически не могут открыть аналитику.
- **Изоляция данных (нет IDOR):** каждый запрос психолога фильтруется по его
  `psychologist_id` — чужой класс/ученика/срез открыть нельзя (404).
- **Одноразовые коды:** код действует только внутри своего среза. Подсмотревший
  его одноклассник больше не может заблокировать ученика навсегда — психолог
  перевыпускает код и удаляет подложные ответы.
- **Пароли:** PBKDF2-HMAC-SHA256, 200 000 итераций, случайная соль, минимум
  8 символов.
- **Серверный выход:** `POST /api/auth/logout` и смена пароля инкрементят
  `token_version` — все выданные токены обесцениваются мгновенно, без
  хранилища сессий. Важно для школьного компьютера.
- **Регистрация только по коду школы**, плюс лимит 5 регистраций в час с адреса.
- **Защита от перебора:** rate-limit на вход, регистрацию, ввод кода **и на
  отправку ответов** — иначе перебор шёл бы прямо на `/submit`, минуя `/start`.
- **CORS выключен по умолчанию**; origin'ы задаются в `ALLOWED_ORIGINS`.
- **Секреты не в коде:** `.env` в `.gitignore`.

### Осознанные ограничения

- **Rate-limit в памяти процесса** — сбрасывается при перезапуске и не
  разделяется между воркерами. Для одного инстанса достаточно; при
  масштабировании выносится в Redis.
- **Токен для скачивания файлов передаётся параметром запроса** (иначе браузер
  не отдаст заголовок при обычной ссылке). Это разрешено только на GET-эндпоинтах
  экспорта, не в основной авторизации.
- **Нет восстановления пароля по почте** — сброс делает администратор школы.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты поднимают приложение на временном SQLite (см. `conftest.py`) — боевая
база из `.env` не используется. Покрыто: аналитика и крайние случаи, поправка
на явку, приватность номинаций «часто один», границы ролей, изоляция данных
между психологами, согласия, одноразовые билеты, оповещения, снапшоты,
ретеншн, журнал доступа, импорт файлов, двуязычные вопросы, профилактическая
работа и оценка эффекта.

## Примечания

- Метрики графа считаются на положительных выборах (кино + проект); вопрос «кто
  часто остаётся один» агрегируется отдельно и никогда не связывается с автором
  номинации — см. раздел «Что психолог видит, а что нет».
- Аналитика закрытого среза кэшируется снапшотом: он же переживает удаление
  сырых данных по сроку хранения.
